## 1. Executive Result

This run deliberately does **not** manufacture a 500-trade profit result when the historical evidence needed for the requested full-system decision is absent.

For every one of the 500 candidate points, the only admissible decision under the requested strict rules was:

**NO_TRADE**

Reason: the market-candle layer is historically available, but the database does not contain point-in-time historical coverage for the other required integrated layers at these timestamps. In particular, the following were unavailable for the selected historical window:

- Historical 35-indicator feature snapshots: **0/500**
- Historical microstructure snapshots (order book / delta / bid-ask notional): **0/500**
- Historical TITAN snapshots: **0/500**

The system's own quality-gate design is fail-closed: unverified research inputs must not be silently replaced with live/current data. The repository's institutional engine also treats data quality and analysis-quality failures as reasons for NO_TRADE rather than inventing evidence.

Therefore, reporting a Long/Short performance result for these 500 cases would violate the requested full-integration and no-look-ahead rules.

### 3.5 Derivatives

The codebase contains a historical-as-of derivatives pipeline for OKX funding, open interest, long/short ratio, and taker volume. The implementation explicitly aligns observations as-of the decision timestamp and avoids using future funding schedules.

However, these historical derivative observations are not persisted in a per-case historical audit table alongside the 500 candidate timestamps. Consequently this report does **not** claim those values as proven evidence for each case.

### 3.6 Macro / on-chain / news

The repository integrates FRED, on-chain/network providers, RSS, GDELT, and other external intelligence for live/contextual analysis.

The repository also states that external REST snapshots are live verification inputs and are **not a substitute for persisted historical streams in backtests**.

For this run there is no persisted point-in-time historical evidence table proving all of the following for every one of the 500 timestamps:

- FRED state as-of the exact decision timestamp

- Etherscan / Alchemy network state as-of the exact decision timestamp
- RSS/GDELT news context as-of the exact decision timestamp

Accordingly these layers are treated as **unverified historical evidence**, not backfilled with current values.

## 4. Decision Logic Applied

The test follows a strict hierarchy:

1. Start from a confirmed 15m historical candidate.
2. Restrict every input to information that existed at or before that timestamp.
3. Require the requested multi-layer evidence to be historically available.
4. Never insert current/live data into a historical timestamp.
5. Never infer missing microstructure, TITAN state, or semantic-35 outputs from future observations.
6. If required evidence is unavailable or unverified, issue **NO_TRADE**.
7. Do not calculate a hypothetical winning trade merely from the future price path.

This is consistent with the repository's fail-closed quality policy and its explicit warning that historical external REST snapshots cannot substitute for persisted historical backtest streams.
